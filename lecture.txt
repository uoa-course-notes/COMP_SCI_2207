+ Securing your web applications 
- Encryption: use HTTPs, enforce https on all traffic to our websites. 
- Use security zones to ensure only authorized users may access the content Use middleware to enforce use permissions across an entite zone.
- Validate all inputs and outputs: using prepared statements. Express-validator has several functions for validating and escaping user inputs. Use innerText instead of innerHTML. 


- Use OpenID where possible to implement password authentication. 
- Allow users to enter all characters (min 160) as long as the it's secure enough. 
- Don't store passwords in plain text instead use hashing algorithms -- such as Argon2, bcrypt. 
- But a hash alone is not enough as there is such a thing called rainbow look-up tables (everyone got together and tries to generate a huge look up tables of hashes).
  So we should salt our password as well =====> Salted hashing -- currently accepted security standard of storing credentials. 
- Assume security will be comprimised (plan ahead if a breach occurs, 2FA)
- Write secure codes -- get a team to review them, run the testing guides over it. 




+ Common threats and Vulnerabilities (3 most prevalent)
- XSS: cross-site-scripting, sanitize data (so an input containing js can occur) 
- SQL Injection: an attack on an app's database (can delete/add records, can pretend to be a user, etc.) 
- CSRF/XSRF: Cross Site Request Forgery -- occurs when a website allows requests that originated from other websites.
